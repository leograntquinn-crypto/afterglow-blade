## 0. 现状快照（对照基线）

| 模块 | 现状（读代码确认） |
|---|---|
| 场景 `scene_vision.gd` | 程序生成 240×240m 高度网格（300 段，约 0.8m 一个顶点），**只有顶点色、没有贴图**；`Environment` 只开了指数雾（密度 0.0045）+ ACES + 弱泛光（0.35）；没有体积雾、高度雾、SSAO、调色；雪粒子是**固定在原点**的 60×60 盒子，不跟镜头；鸟居和立石都是 BoxMesh；草是 4,200 片 BoxMesh 刀片；地形**没有碰撞**；背景是纯色，没有远山和天空；镜头约 30° 俯角、约 8.5m 距离 |
| 镜头 `arena3d.gd` | SpringArm3D 撞墙后会往前推（不是淡出遮挡物）；FOV 65；俯角 −0.32 rad（约 18°，**离 45° 目标很远**）；滚轮缩放 4–10m（范围太宽）；没有焦点缰绳 |
| 玩家 `player3d.gd` | 三连斩，每段 22 帧、第 6 帧判定、第 10 帧起可衔接，伤害 12/12/16；判定是 2.1m 半径、±70° 的扇形；出招时用 1.2m/s 小幅前冲，**没有吸附**；**没有闪避、格挡**；输入缓冲只在第 10 帧之后记录，**顿帧期间的按键会丢**（冻结时 `_physics_process` 直接 return，`previous_attack` 不更新，冻结期间按下又松开就没了） |
| 顿帧 | **全局冻结**（`stage.frozen` 停住所有实体），轻击 6 帧、终结 8 帧——正是 guizang 点名会"发黏"的做法 |
| 敌人 `enemy3d.gd` | 只有 BoxMesh 代理体；蓄力 21 帧、恢复到第 49 帧、冷却 46–84 帧；防连晕链已移植（这点比 guizang 强）；**每个敌人各自决定出手，没有轮流进攻的令牌**；击退 0.04 / 0.07m（这是从 2D 像素换算来的，3D 里几乎看不出来）；判定半角写的是 70°，**和 C4 工单的 60° 对不上**（C4 工单已作废，但其帧数据由 3D 战斗线继承，统一以 60° 为准写进 `data/combat_frames.json`） |
| 身体碰撞 | 玩家层 2、敌人层 4，两边的 mask 都只有 1 → **玩家和敌人互相穿过去** |
| 特效 | 一段 ImmediateMesh 扇形加顶点色，0.12 秒淡出，没有噪声、侵蚀和节奏 |
| 动画 | Tripo 预设片段；`_pin_root` 把 Hips 的**局部** x/z 钉在首帧 → guizang 指出的"父节点有倾斜时清不干净"的风险还在；攻击是把 5.3 秒的片段从 1.0 秒处起播、5 倍速，**动作节拍和判定帧没有对齐** |
| 弹簧骨 | 没有（3D 侧没有任何 SpringBone 相关代码） |
| 验证 | 已经有 headless `--verify` / `--capture` 和 `tools/verify_c4.gd`，比 guizang 在浏览器里手动推帧更容易自动化 |
| C4 工单 | **已作废**（Quinn 2026-11-12：2D 先不做了）。2D 渲染层（精灵、Y-sort、八方向）全部停止；**工单沿用的 C1 战斗帧数据和防连晕规则已被 3D 战斗线继承，继续有效**。`tools/verify_c4.gd` 里与渲染无关的帧数据 / 防连晕断言迁入 `combat3d --verify` / `tools/verify_feel.gd` 后，这个脚本退役 |

## A. 吸收清单

图例：**✅ 已有**｜**◐ 部分有**｜**✗ 缺失**。"Godot 实现"一列写到节点、着色器或代码结构这一层，Codex 可以直接照着拆工单。

### A1. 渲染底座与氛围

| # | guizang 做法 | Godot 实现方式 | 现状 | 差距 |
|---|---|---|---|---|
| A1.1 | 先搭渲染底座：HDR → AO → 体积雾 → 多级泛光 → 调色（色调映射 + 分离色调 + 暗角）→ 抗锯齿 + 颗粒 | 单独一个 `res://env/afterglow_night.tres`（Environment 资源），场景共用：`tonemap_mode = TONE_MAPPER_AGX`；`ssao_enabled`；`volumetric_fog_enabled`；`glow_enabled` 并开 2–5 级；`adjustment_enabled` + `adjustment_color_correction` 用 3D LUT 做分离色调；暗角和颗粒用 `CompositorEffect` 或一层 CanvasLayer 全屏 shader（读 `hint_screen_texture`）；`Viewport.use_taa = true`，或 `msaa_3d = 4x` + FXAA | ◐ | 现在只有 ACES、指数雾和弱泛光，没有 AO、体积雾、LUT、暗角、颗粒，Environment 也写死在脚本里，不能复用 |
| A1.2 | 体积雾采样阴影，点光源带光晕 | `volumetric_fog_*`（参数见 C4）；每盏暖光设 `light_volumetric_fog_energy = 2.0`，月光设 1.0；`DirectionalLight3D.shadow_enabled` 打开后体积雾会自动吃阴影 | ✗ | — |
| A1.3 | 夜景：一盏冷色主光 + 若干暖色点光 | 冷月光 `DirectionalLight3D` + 3–5 盏 `OmniLight3D` 篝火/灯笼，都挂在点缀物下面，不单独散放 | ◐ | 冷主光已有；暖光只有 1 盏，而且是孤立放的 |
| A1.4 | 天气盒：跟镜头走的盒子里循环雪、贴地薄雾和风线；全图都有天气，但只模拟镜头附近 | `WeatherRig`（Node3D）每帧把位置设成镜头焦点；子节点是 ① `GPUParticles3D` 雪（`local_coords = false`，发射盒 32×1×32m，放在焦点上方 10m）；② 贴地雾片（`MultiMeshInstance3D`，24 片 6×2m 面片，用滚动噪声 shader 并做深度软化）；③ 风线（`GPUParticles3D` 拉伸的细长面片，数量 30）。`visibility_aabb` 设 40×20×40 | ◐ | 有雪，但盒子固定在原点，走出 60m 就没雪了；贴地雾和风线都没有 |
| A1.5 | 地面着色器里加一层成片积雪：噪声控制分布，积水和陡坡上没有；第一版通常盖太满 | 地形 shader 里算 `snow = smoothstep(a, b, noise(world.xz*0.03) + 坡度项) * step(0.78, N.y) * (1 - wet)`，再和岩石高度图做高度混合（height blend），不做线性插值。覆盖率要能调，并能输出调试视图（见 C3） | ◐ | 现在是顶点色按坡度插值，没有噪声分片、高度混合、湿度遮罩 |
| A1.6 | 地面、石头、泥土用 CC0 整套 PBR（颜色、法线、粗糙度） | Poly Haven CC0：雪、裂纹岩、冻土、枯草地四套，2K 源 → 进游戏 1K（主地面可以 2K），用 `Texture2DArray` 喂给地形 shader | ✗ | 现在完全没有贴图 |
| A1.7 | 植被用实例化网格自己铺 | `MultiMeshInstance3D` 按 32m 分块（每块一个 MMI，方便视锥剔除），草丛用交叉面片 + alpha scissor + 风摆顶点 shader；**弯曲量要除以实例的水平缩放**（guizang 踩过的坑） | ◐ | 有 MultiMesh，但只是一个整体，刀片是 BoxMesh，也没有风摆 |
| A1.8 | 走动时脚下扬起雪尘，留下会淡掉的脚印 | 脚印：容量 48 的 `Decal` 环形池，从动画事件 `foot_l/foot_r` 触发，存活 8 秒线性淡出；雪尘：每步 6–10 粒 `GPUParticles3D` one_shot。只在雪面（取样雪层遮罩 > 0.5）上生效 | ✗ | — |
| A1.9 | 标题画面直接显示实时场景 | 标题菜单叠在 v5 场景上，镜头每秒缓慢绕 3° | ✗ | 放到 UI 阶段再做 |
| A1.10 | 远景：大场景要有空气感和远山 | `ProceduralSkyMaterial` 或渐变天空 + 一圈 250–400m 外的远山剪影网格（unshaded，只吃雾），`fog_aerial_perspective = 0.4` | ✗ | 现在背景是纯色 |

### A3. 动画方法

| # | guizang 做法 | Godot 实现方式 | 现状 | 差距 |
|---|---|---|---|---|
| A3.1 | 在角色空间写姿势（+Y 上、+Z 前、米），每个关键姿势指定髋位移、脊柱/头转角、手目标、剑指向、脚落点；手臂和腿用两骨 IK + 肘膝朝向提示；烘焙成片段 | **离线烘焙工具** `tools/pose_bake.gd`（headless SceneTree 脚本）：读 `data/poses/*.json` 关键姿势 → 在 `Skeleton3D` 上用 `TwoBoneIK3D`（4.6 起引入的 IK 修饰器，如果 4.7 的 API 不符合，就自写解析解：余弦定理求肘角 + pole 平面）求解 → 按 30fps 采样骨骼局部旋转 → 写成 `Animation` 存进 `res://anim/feisun_moves.res`（AnimationLibrary）。运行时**不跑 IK**，只播烘焙好的片段，可以和 Tripo 预设动作交叉淡入 | ✗ | 现在完全靠 Tripo 预设动作加速播放 |
| A3.2 | 数值探针：打印某一帧各关节相对根的位置，用数字核对 | `pose_bake.gd --probe=<clip>@<t>`：输出 hand_r / hand_l / foot_* / head / sword_tip 在角色空间的坐标；配套断言（例如"挥出帧 hand_r.z > 0.35"，"所有帧脚底 y ∈ [−0.02, 0.05]"，除非是跳跃片段） | ✗ | — |
| A3.3 | 一招至少五拍：起手 → 蓄势停顿（更深一点，约 0.08 秒）→ 快速挥出（四次方缓出）→ 随势过冲 → 收回到战斗待机 | 对齐现有 22 帧三连斩，改成：起手 0–2 / 蓄势 3–5（停 5 帧 ≈ 0.083s）/ 挥出 5–8（`ease_out_quart`，**判定帧 6–7**）/ 过冲 8–11 / 收回 11–22（第 10 帧起可衔接，第 16 帧起可以从收回段直接接下一段）。第三段（重击）：蓄势加长到 7 帧，判定帧挪到第 8–9 帧，总长 28 帧 | ✗ | 现在判定帧和动作节拍没有对齐 |

## B. 超越清单

guizang 的定位是"一个下午做出来的单场景 demo"。下面这些是我们明确比它走得更远的地方，每条都要落成可验收的标准，不能只停留在口号。

### B1. 全游戏结构与成长系统
- **差别**：他是"一个场景 + 一段小怪战 + 一个 Boss"；我们是五关卡、精英、Boss、剧情推进，加装备十槽、词条、掉落规则和存档（`data/gear_catalog.json`、`drop_rules.json`、`statuses.json`、`SaveGame`）。
- **验收标准**：
  1. v5 场景地图上至少有 3 个战斗区、1 个精英点、1 个 Boss 场、2 个剧情触发点，从出生点走到 Boss 场的主路径 ≥ 180m。
  2. 掉落表现档位和 `drop_rules.json` 的稀有度一一对应（A4.7），拾取后的装备能在背包里看到、装上之后数值生效（headless 断言：装备前后攻击力差 = 词条值）。
  3. 存档后读档，恢复位置（误差 < 0.1m）、装备、已清的战斗区，打过的 Boss 不会重生。
  4. 防连晕规则（链窗 75 帧、第 4 次挣脱 80 帧、重击必断；源自已作废的 C4 工单，由 3D 战斗线继承）在新的按角色顿帧下继续通过 `combat3d --verify`。

### B2. 弹簧骨飘动（他明确写了"没做但值得做"）
- **差别**：他的宽袖、长发、披风都跟着骨骼硬动；我们给绯隼的马尾和红腰带、烬翼的尾羽和翼尖做运行时弹簧骨。
- **方案（已定，Quinn 裁决 4）**：**运行时弹簧骨模拟**，在 Godot 侧每个物理帧做 verlet 积分 + 弹簧 / 距离约束求解。不做离线烘焙，不做八方向缓存，不把飘动烘进动画片段。
- **Godot 实现**：求解器挂在 `Skeleton3D` 下，作为 `SkeletonModifier3D` 运行（在动画姿势写入之后、渲染之前）。首选承载是引擎内置的 `SpringBoneSimulator3D`（它本身就是 verlet + 弹簧约束的求解器），每条链单独设置；碰撞体用 `SpringBoneCollisionSphere3D` / `Capsule3D`，挂在头、胸、骨盆、大腿上。如果内置节点满足不了下面某条验收（固定 60Hz 步长、随角色顿帧冻结），就自写一个 `SkeletonModifier3D` 子类实现同一套 verlet 求解，参数和验收不变。求解步长固定为 1/60 秒，渲染帧之间插值，不跟着渲染帧率走。
- **废止**：`CHARACTER_3D_PIPELINE.md` 第 9 步"物理离线烘焙、八方向共用缓存"的写法属于已作废的八向精灵路线，以本条为准（那份文档的措辞另行同步，不在本文改动范围内）。
- **初始参数**（马尾 5 段骨）：stiffness 0.6、drag 0.35、gravity 0.4（向下）、根部第 1 段 stiffness 1.5（近似锁死）；腰带 2 条 × 3 段：stiffness 0.9、drag 0.5、gravity 0.6。
- **验收标准**：
  1. 跑步 → 急停：马尾尖在 **0.6–0.9 秒**内停稳（位移振幅 < 2cm），不能一直抖。
  2. 跑步中，马尾尖相对头骨的滞后角 15°–35°。
  3. 全套动作（含三连斩、闪避、倒地）中，马尾和腰带都不穿进头、躯干、大腿（碰撞体检测：穿透深度 < 1cm，headless 逐帧扫描）。
  4. 帧率无关：用 30 / 60 / 144 FPS 各跑同一段 3 秒录制输入，马尾尖轨迹的最大偏差 < 3cm。
  5. 角色顿帧时弹簧骨也冻结（不然定格画面里头发还在飘，会破坏定格感）。

### B3. 角色资产：权重重涂与"三验"标准
- **差别**：guizang 直接用平台绑骨加预设动作；我们的管线规定平台绑骨只算初稿，必须在 Blender 里转进项目骨架规范、重涂权重（`CHARACTER_3D_PIPELINE.md` 第 6–7 步）。
- **"三验"正式定义**（按我们实际执行的口径，Quinn 裁决 4）：
  1. **① 权重普查**：逐骨统计**主导组占比**（每根骨影响到的顶点里，它是最大权重的那部分顶点所占的比例，用来发现"挂名但不主导"或被邻骨抢走的骨），以及**全模型权重总和分布**（每个顶点权重总和的直方图，必须集中在 1.0；偏离的顶点逐个列出）。附带脚本断言：每个顶点影响骨数 ≤ 4、微权重 < 0.01 已清理、权重已 normalize。
  2. **② 杠杆扫描**：**逐骨旋转 0.6 rad**，测量各探针点（手、脚、头顶、马尾尖、腰带尖、武器挂点，以及该骨所在区域的体表探针）的位移。用来抓出"转一根骨却带动了不该动的部位"（串权重）和"该动的部位不动"（漏权重）的问题；每根骨输出一行位移表，异常项单独标红。
  3. **③ 姿势与全动画渲染验收**：压力姿势全套（抬臂 170°、抱胸、举刀过头、深蹲、跨步、扭腰 60°、倒地）加上**全部游戏动画片段**逐一渲染出帧，**必须包含脸部特写帧和双手特写帧**；同时在**游戏镜头**（C6.3 的默认俯角和距离）下播完全部片段。检查塌肩、腿粘连、穿模、脸部变形、手指 / 握持错位（武器握持偏差 < 1cm）；预设片段清理后，跑 10 秒的 Hips 水平漂移 < 2cm（A3.4）。**只做静态或单姿势的验收不算数。**
- 三验各出一份数值报告（① ② 是表，③ 是截图集 + 帧索引），放进资产目录 `qa/`，缺一项不算交付。

### B4. 原生 Godot / Steam，而不是 WebGL 单文件
- **差别**：他是一个约 30MB 的 HTML，受限于 WebGL（体积雾只能自写近似、阴影和泛光都要省）。我们是 Forward+ 原生：真体积雾、SSAO、TAA、PSSM 阴影都有，还要做 Steam 发行（成就、云存档、手柄）。
- **验收标准**：
  1. **画质三档预设**（低 / 中 / 高），由 `Settings` 切换：低档关体积雾和 SSAO、阴影 2 级、草密度 50%；高档全开。
  2. **性能**：开发机 1080p 高档 ≥ 60 FPS（C 场景 P1–P6 每个点位的 1% low ≥ 50）；Steam Deck（1280×800）低档 ≥ 40 FPS 稳定（Deck 验证要等拿到设备，或用同级 GPU 估算，报告里要注明是哪一种）。
  3. **手柄是第一公民**：所有战斗动作都能用手柄完成，有震动反馈（命中 0.08 秒弱震，弹反 0.15 秒强震）。
  4. Steam 集成走 GodotSteam（GDExtension），存档同时写本地和 Steam Cloud。**这一项不进 v5 场景工作包**，只在这里冻结接口。
- 他的打包经验里，只有一条对我们有用：**带骨骼的角色导入时不要做顶点量化**，打包前后要逐个角色对比头部高度和根节点缩放。Godot 导入 GLB 的时候也要检查：`feisun_gen4` 在编辑器和导出包里的头顶高度一致（误差 < 1mm）。

### B5. 可旋转镜头与 360° 场景
- **差别**：他是固定斜俯视，场景只需要做朝镜头的那一面；Quinn 已经定了"镜头可旋转、场景美术 360° 做满"（2026-11-11 18:50）。
- **验收**：C8 的 P6 点位必须在镜头转 0° / 90° / 180° / 270° 四个朝向各截一张，四张都不能露出背板、空洞或没摆东西的方向；遮挡淡出（C6.5）在任何朝向都要生效。

### B6. 数据驱动 + 无头自动验收
- **差别**：他靠浏览器里手动推帧加截图；我们的战斗规则是帧数据表，每个工单都有先行验收脚本（`--verify`；已作废的 C4 工单留下的 `tools/verify_c4.gd` 中帧数据 / 防连晕断言迁入 `verify_feel.gd` 继续跑），能放进 CI 跑。
- **验收**：本文 D 部分的每一项增量都必须带一个 headless 断言（D 部分每条最后一行就是断言），全部合并进 `tools/verify_feel.gd`，最后一行输出 `FEELVERIFY PASS / FAIL n`。

## C. 场景 v5 工作包规格

> **范围说明（Quinn 裁决 3，2026-11-12）**：v5 **只做第一关雪原**。本部分所有地貌、雪层、雾层、点缀物和调色参数都只针对第一关；**其余四关的场景题材逐关另定**，不默认沿用雪景。为了不给后面几关挖坑，只要求两点：地形 shader 的分层结构（4 层 PBR + 控制图 + 高度混合）和 `Environment` 资源按"每关一份"组织（`env/<关卡名>.tres`、`data/<关卡名>_layout.json`），雪层作为第一关的专有层实现，不为"换季节 / 换地貌"预先做通用化。
> 本文下面提到的"C4"一律指本部分的 **C4 雾层**小节，不是已作废的 C4 竖切工单。

### C2. 地面材质（`terrain_v5.gdshader`）
- **四个 PBR 层**（Poly Haven CC0，进游戏 1K，主雪层 2K）：L0 雪、L1 裂纹岩、L2 冻土、L3 枯草地，用 `Texture2DArray` 装 albedo / normal / roughness。
- **控制图**：`splat_v5.png`（RGBA，1024²，覆盖 384m，约 0.375m/像素），用工具生成后可以手修。
- **平铺尺度**：细节层每 2.5m 平铺一次；另外叠一层 40m 尺度的宏观明暗噪声（±8% 亮度），专门用来消除平铺重复感。
- **陡坡**：坡度 > 35° 改用三平面映射的岩石层。
- **混合方式**：高度混合（用岩石层高度通道做 `height + weight` 比较，过渡宽 0.08），**禁止线性插值**（线性混合会糊成一片，就是"一张纯色贴图糊过去"的感觉）。
- **细节必须有**：裂纹（L1 本身的法线 + 额外 12–20 个裂纹 `Decal`，2–5m 大小，只放在石地区和战斗区）、积雪深浅、主路上的拖痕。
- 色调：雪层 albedo 压到 0.72–0.78（**不能用纯白**，冷色调下纯白雪在泛光里会成片发光）；岩石 0.18–0.25。

### C3. 雪层
- 公式：`snow = clamp(smoothstep(0.35, 0.65, n_macro + 0.25*n_detail) * smoothstep(0.72, 0.86, N.y) * (1.0 - wet) * splat.r_bias, 0, 1)`；`n_macro` 是 0.03 频率的世界坐标噪声，`n_detail` 是 0.4 频率。
- 和岩石做高度混合：`snow_final = step(rock_height + 0.15, snow * 1.2)` 再柔化 0.06。
- **覆盖率目标**：默认镜头（P1）画面里可见地面的 **35–50%** 是雪（用 `--debug-view=snowmask` 截图统计白色像素占比）。guizang 说第一版一定盖太满，我们直接给上限 50%。
- 积水和冰面区（`wet = 1`）没有雪；陡坡（> 40°）没有雪。
- 角色脚下：雪层 > 0.5 时触发脚印 Decal 和雪尘（A1.8）。

### C6. 光照、调色与镜头

**C6.1 光照**
- 月光 `DirectionalLight3D`：颜色 (0.70, 0.78, 1.0)、能量 1.0、仰角 35°、方位和默认镜头成 120°（侧逆光，让角色有轮廓）；阴影 PSSM 4 级，`directional_shadow_max_distance = 70`，`blend_splits = true`；`light_volumetric_fog_energy = 1.0`。
- 环境光：`ambient_light_source = SKY`（如果用纯色就设 (0.42, 0.47, 0.66)），能量 0.45。
- 暖光：4 盏 `OmniLight3D`，颜色 (1.0, 0.56, 0.26)、能量 3.5、范围 12m、`light_volumetric_fog_energy = 2.0`，带 ±8% 的 2Hz 噪声闪烁；**暖光在画面里的面积 ≤ 10%**（只是点缀）。
- 角色补光：跟随主角的一盏 `OmniLight3D`，冷白色 (0.8, 0.85, 1.0)、能量 0.6、范围 3.5m、不投影——保证角色在暗处也能读得清。

**C6.2 调色**
- `tonemap_mode = AGX`，`tonemap_exposure = 1.0`（拿 P1 截图再调，范围 0.85–1.15）。
- 泛光：开 2、3、4、5 级（权重 0.4 / 0.8 / 1.0 / 0.6）；`glow_intensity = 0.6`；`glow_bloom = 0.04`；`glow_hdr_threshold = 1.0`；`glow_blend_mode = SOFTLIGHT`（如果特效被吃掉就改 ADDITIVE，intensity 降到 0.4）。
- SSAO：`radius = 1.2`、`intensity = 1.6`、`power = 1.5`；SSIL 默认关（中、高档可以开）。
- 调整：`adjustment_contrast = 1.06`、`saturation = 0.88`；3D LUT（33³）做分离色调：暗部推向 (0.30, 0.33, 0.55)，亮部推向 (1.00, 0.93, 0.88)，混合强度 0.35。
- 暗角：强度 0.22，从屏幕半径 0.65 处开始；颗粒：0.025，每帧变化。
- 整体目标：冷色（蓝紫）占画面主体，暖光只是点缀；角色和特效是画面里对比度最高的东西。

**C6.3 镜头（`CameraRig3D`）**
| 参数 | 规格 |
|---|---|
| 俯角 | 默认 **45°**，玩家可以调的范围 38°–55° |
| 距离 | 默认 16m（焦点到镜头）；缩放倍率锁在 0.95–1.3（15.2–20.8m），滚轮每格 0.05 倍，带 0.2 秒平滑 |
| FOV | 38°（竖直）——镜头越远、FOV 越小，透视畸变越小，越接近参考图那种"俯瞰大地"的感觉 |
| 构图 | 焦点 = 主角位置 + 上 1.0m；主角在屏幕上的高度占视口高度的 **9–14%**；主角位于屏幕竖直方向 52–58% 处（中心略偏下，符合标杆的"画面中心偏下"） |
| 旋转 | 按住右键拖动或用手柄右摇杆，偏航角自由（Quinn 已定可旋转）；松开后保持当前角度，**不自动回正**；需要回正时由玩家主动按"一键回正"（C6.4） |
| 缰绳 | 焦点最多偏离主角 3.5m；Boss 战时焦点往 Boss 偏 25%，但偏移上限还是 3.5m；鼠标或右摇杆的前视牵引 ≤ 0.6m |
| 跟随 | 位置用临界阻尼弹簧（`smooth_damp`），平滑时间 0.18 秒；过场交还控制时，跟随速度在 0.6 秒内从 20% 平滑升到 100% |
| 地形 | 镜头高度每帧和"地形高度 + 1.5m"取大 |
| 遮挡淡出 | 每帧对注册了的遮挡物（鸟居、枯树、立石群、灯笼，放在 `occluder` 组里）计算它到"镜头—主角"连线的水平距离，小于 `物件半径 + 0.6m` 就在 0.15 秒内淡到 alpha 0.25（用 `GeometryInstance3D.transparency`，不是换材质），离开后 0.3 秒恢复。**不用 SpringArm 把镜头往前推**（镜头一推近，构图和手感都会变） |
| 震屏 | 沿用现有 trauma 模型（上限 0.6，衰减 1.8/s），振幅按镜头距离等比放大（16m 下乘 2.0），让远镜头下也看得出来 |

以上参数（俯角 45°、距离 16m、FOV 38°、缰绳 3.5m、遮挡淡出）已由 Quinn 裁决 1 通过。

**C6.4 一键回正（Quinn 裁决 1 新增）**
| 项 | 规格 |
|---|---|
| 动作名与默认按键 | `InputMap` 动作 `camera_recenter`，可改键。默认：**鼠标中键单击**、键盘 **`C`**、手柄 **右摇杆按下（R3）**。只认按下边沿，按住不重复触发 |
| 回正目标 | **偏航**：回到"主角身后"的默认方位，即镜头偏航 = 主角**模型当前朝向**（不是输入方向）在按下那一帧的值，镜头从主角背后看向主角面朝的方向；Boss 战中（C6.3 的 Boss 偏置生效时）改为"主角身后、面朝 Boss"，即偏航 = 主角指向 Boss 的水平方向。目标在按下那一帧**锁定**，过渡途中主角转身不追（避免镜头跟着乱摆）。**俯角**：同时回到默认 45°。**缩放**：不动，保留玩家自己调的倍率 |
| 路径 | 偏航走最短弧（\|Δ\| ≤ 180°）；\|Δ偏航\| < 2° 且俯角差 < 1° 时视为已正，不播过渡 |
| 时长 | 按转角给时长：`T = round(10 + 14 × \|Δ偏航\| / 180°)` 帧，即 **10–24 帧（0.17–0.40 秒）**；转 90° 约 17 帧。俯角和偏航共用同一个 T，同时到位 |
| 缓动 | **ease-out cubic**（`1 − (1 − t)³`）：起步快，按下就有反应；收尾柔和，不会"咔"地停住。时间按**实时**走，不受 `Engine.time_scale`（完美闪避 / 处决慢镜头）和角色顿帧影响 |
| 期间：镜头旋转输入 | 右键拖动超过 2 像素，或右摇杆超出 0.2 死区 → **立即中止回正**，从当前角度直接交给玩家，不跳回、不补完 |
| 期间：缩放 | 滚轮缩放照常生效，和回正同时进行 |
| 期间：移动输入 | 移动方向本来是"相对镜头"的；回正期间，移动参考系**锁在按下那一帧的镜头偏航**，主角不会因为镜头在转而走出弧线。回正结束后，只要摇杆 / 方向键一直按着、方向变化不超过 30°，就继续沿用旧参考系；松开或方向变化超过 30° 时才切到新的镜头参考系 |
| 期间：战斗输入 | 攻击、闪避、举剑、反击全部照常，回正不吃任何战斗输入，也不打断任何战斗状态 |
| 期间：再次按回正 | 以当前角度为起点、当前主角朝向为新目标，按剩余转角重新计算 T 再走一遍 |
| 不响应的时段 | 处决镜头（D10）、过场、Boss 开场演出期间，回正输入直接忽略（不缓冲）；控制权交还后才能用 |
| 跟随 | 回正只改偏航和俯角；焦点位置的弹簧跟随、缰绳、地形取大、遮挡淡出照常每帧运行 |
| 断言 | 偏航 0°、主角朝向 150° 时按回正 → 第 0 帧开始转动，第 T = 22 帧时偏航 = 150° ± 0.5°、俯角 = 45° ± 0.2°；途中第 8 帧注入右摇杆输入 → 当帧中止，偏航不再向 150° 靠近；回正期间按住"前"，主角的世界移动方向与按下那一帧的方向偏差 < 1° |

### C8. 验收截图点位与通过标准
截图分辨率统一 1920×1080，高档画质；每个点位固定种子、固定时刻（t = 3.0 秒，等雪和雾稳定下来）。

| 点位 | 位置 / 镜头 | 必须看到 | 通过标准（数值） |
|---|---|---|---|

### D1. 统一输入缓冲
- 缓冲窗口：攻击 **10 帧**（0.167 秒）；闪避 **8 帧**；举剑（格挡 / 弹反）**6 帧**；反击 12 帧（反击和攻击是同一个键，在反击窗口内按攻击即记为反击）。举剑缓冲故意短：弹反讲究时机，缓冲太长会让玩家"提前按也弹到了"，失去判断感。
- 寿命只在"自身没被冻结"的帧里减少（顿帧期间按的键，等顿帧结束后仍然有效）。
- 消费时机：攻击在当前段的 cancel 帧（现在是第 10 帧）消费；闪避随时消费（见 D8 的取消表）；举剑按 D10.5 的取消表消费。
- 优先级：闪避 > 举剑 > 反击 > 攻击；同一帧只消费一个（详细见 D10.5）。
- 输入边沿检测要放在冻结检查**之前**。
- 断言：顿帧第 2 帧按下攻击并在第 3 帧松开 → 顿帧结束后当段 cancel 帧时自动进入下一段。

### D2. 攻击吸附
- 搜索：半径 **4.0m**，以输入方向为中心的 **±60°** 扇形（没有输入时用角色朝向）；高差 > 1.0m 的敌人不算。
- 评分：`score = d / 4.0 + |Δθ| / 60° × 0.8`，取最小值。
- 转向：出招第 0 帧直接转向目标（瞬间转身，最大 180°）。
- 站位距离：`standoff = 玩家半径 0.3 + 敌人半径 0.32 + 0.9 = 1.52m`（REACH 2.1 内留 0.58m 余量）。
- 滑步：在第 1 到 5 帧（判定帧之前），单段最大滑步距离第一、二段 **2.0m**，第三段 **2.6m**；每帧 `step = min(剩余滑步 / 剩余帧数, max(0, 当前距离 − standoff))`，所以永远不会冲过头。
- 没有目标：只做 0.35m 的前冲（替代现在 1.2m/s 的速度写法）。
- 滑步用 `move_and_collide`，撞到墙或障碍就停。
- 断言：敌人在 3.5m、偏 40° 处 → 第 6 帧时距离 ∈ [1.45, 1.60]m 且朝向误差 < 3°，命中；敌人在 5m → 不吸附，只前冲 0.35m。

### D3. 身体推挤
- 碰撞层：玩家 mask 加上敌人层（4），敌人 mask 加上玩家层（2）和敌人层（4）。
- 软分离：两个胶囊水平距离 < 半径和时，各沿连线推开重叠量的 50%，单帧最多 0.08m。
- 例外：玩家闪避中（D8 无敌帧期间）、敌人倒地（`down` 状态）不参与推挤。
- 断言：玩家顶着敌人走 60 帧，两者水平距离始终 ≥ 0.58m（= 半径和 0.62 − 容差 0.04）。

### D4. 敌人攻击令牌
- 近战令牌上限 **1**，远程令牌上限 **1**（远程和近战可以同时出手）。
- 持有期：从蓄力第 0 帧到恢复结束后再加 **20 帧**；然后释放，下一个申请者要再等 **30–60 帧**（随机，种子固定）才能拿到。
- 没拿到令牌的敌人：进 `circle` 状态，在离玩家 **3.5–5.0m** 的环上横移，速度 1.0m/s；每 90–150 帧换一次方向。
- 精英：可以无视令牌，但精英出手时普通小怪不能出手。Boss：独立，不占令牌，Boss 出招期间所有小怪的令牌冻结。
- 断言：3 只腐骨兵同时在 2m 内，任意时刻处于 `atk` 状态的近战敌人数 ≤ 1（扫描 600 帧）。

### D8. 闪避
- 总时长 **22 帧**；位移 **3.2m**，按 ease-out cubic 分配（前 8 帧走完 70%）。
- 无敌帧：**第 2–13 帧**（12 帧 = 0.2 秒）。
- 方向：有输入时用输入方向，没有输入时往角色背后。
- 取消规则（闪避可以打断什么）：

| 当前状态 | 能否闪避 |
|---|---|
| idle / walk / run | 能 |
| attack 任意帧（含判定帧） | 能 |
| 攻击方顿帧期间 | 能（立即结束自己的冻结） |
| 举剑 / 格挡 / 格挡僵直（D10） | 能（弹反窗口内也能，闪避优先，弹反判定随之结束） |
| 破防硬直（D10.1） | **不能** |
| hurt 硬直 | **不能** |
| 大招 / 处决动画 | **不能** |

- 闪避之后：第 16 帧起可以接攻击（缓冲的攻击在第 16 帧消费）。
- 连续限制：连续闪避 2 次之后，第 3 次需要等 **20 帧**。**闪避不消耗体力**：D10 引入的体力只服务格挡，这样"闪避优先级最高、随时可用"的原则不会被体力打空破坏，格挡和闪避的取舍靠收益区分（格挡 / 弹反能开反击窗口，闪避不能）。
- 断言：敌人判定帧落在玩家闪避第 5 帧 → 玩家 HP 不变；第 15 帧 → 掉血。

### D10. 格挡 / 弹反 / 反击 / 处决（Quinn 裁决 2：全部要做）
参考了 guizang `combat-feel.md` 的思路（正面格挡扣体力、约 0.24 秒弹反、约 0.85 秒反击窗口、瞬移 + 慢镜头 + 剑气的处决），数值全部按我们的 60Hz 帧体系重新定，并补上它没写的部分（举剑收势、防乱按、连续弹反、同帧结算顺序、破势条）。所有数值写进 `data/combat_frames.json` 的 `guard` 段。

**D10.0 输入与状态流**
- 一个键 `guard`（默认：键盘 `Q`、鼠标侧键 4、手柄 L1；鼠标右键已给镜头旋转，不占用）。**按下 = 举剑（含弹反窗口），按住 = 格挡。**
- 状态流：按下 → `guard_raise`（第 0–12 帧）→ 仍按住 → `block`；第 12 帧前松开 → 举剑照样走完第 12 帧，再进 `guard_lower`（8 帧，**仍有格挡判定**）→ idle。`block` 中松开 → `guard_lower` 8 帧 → idle。

### D11. 场地平滑并集 + 卡点扫描
- 场地 SDF：`d = smin(circle_1, circle_2, ..., k = 3.0) + noise(p * 0.15) * 0.8`；`d < 0` 是可走区域。
- 一排障碍物用一条胶囊碰撞，**圆形碰撞之间的间隙必须 ≥ 0.8m 或者干脆合并**（否则会形成挂人的凹角）。
- 关闭区域（例如 Boss 开场封住来路）之前，先把主角传送到预设的安全点（`safe_spawn`），再关门。
- 卡点扫描（`tools/verify_stuck_scan.gd`，headless，只跑逻辑不渲染）：在每个战斗区里按 **1m 网格**取点，每点 8 个方向各推进 **40 帧**，从停下的位置再试 8 个方向各推进 40 帧，只要有一个方向能移动 ≥ 1.0m 就算"没卡住"。
- 断言：卡住点数 = 0；碰撞解不开时退回上一帧位置（永远不接受非法位置）。

### D12. 完美闪避慢动作
- 触发：敌人判定在玩家闪避的 **第 2–7 帧**（无敌帧前半段）和玩家重叠。
- 效果：`Engine.time_scale = 0.3`，持续 **24 帧（实时）**，然后 6 帧内线性恢复；回复一格资源（如果有技能资源）；画面短暂去饱和（saturation 0.88 → 0.5，0.1 秒进 0.2 秒出）。
- 同一次攻击只触发一次，冷却 120 帧。
- 断言：触发后 `Engine.time_scale == 0.3`，24 个实时帧之后恢复到 1.0。
