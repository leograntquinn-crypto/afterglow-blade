## 一、架构裁定：你的设想成立，但落地形态是「混合式模块化」

**结论：基础人体 + 统一骨架 + 零件换装，方向正确。** 但有三条现实修正：

1. **只有会换装的角色走全模块化（主角绯隼、未来的可玩角色）。** 敌人、Boss、NPC 的服装是固定的——它们用「身份整套」生产（带衣整模绑到对应骨架族即可），不为理论上的换装把衣服拆开。这省掉全阵容里最大的一块适配与遮挡测试量。
2. **3D 源件独立 ≠ 游戏里每槽一层图。** 衣裤靴在 3D 里保留独立源件，但渲染进游戏时默认合成「身体外观包」一层；武器、翅膀保持独立层。原因是遮挡：同一把刀在一帧内可能一半在胸前一半在手后，固定层序必然露馅（见第五节）。
3. **自由混搭有组合爆炸问题**：衣裤靴头武五槽 × 7 系列 = 16,807 种视觉组合，不可能全部预渲染。**Quinn 已拍板（2026-11-11）：选 B 档——视觉任意混搭，走深度合成路线**（每槽独立分层渲染 RGBA+深度，Godot 自定义 shader 逐像素按深度合成），作为单独立项推进；逻辑装备十槽独立（数值、词条照旧）不变。代价与门槛见第 5 节：M1 必须先验证深度合成原型（精度、半透明边、性能、显存），不过关不扩产。

资产四级：**身份参考**（带衣高质量模型/设定图，锁脸、马尾、剪影、配色）→ **标准形体**（男女标准人体 + 身份头部/发型）→ **装备母版**（独立源件）→ **游戏外观**（外观包 + 武器包 + 翅膀包，版本与动作/方向/锚点严格同版）。

## 二、平台分工（已实查）

| 平台 | 在管线中的位置 | 已确认能力与边界 |
|---|---|---|
| **Rodin（Hyper3D）** | 主力「生」：身份母版与高模形体 | 身份还原是我们实测最强的；human skeleton 绑骨可用作初稿。教训入册：①材质生成选 4K（选 8K 后打包只剩 4K/8K 档、丢 2K 选项）；②生成/确认后**立即下载**并校验完整性，云端历史不算交付（v3 包 7 次点击零交付的教训）；③它也有 BANG 拆件，分割不是 Tripo 独占，比的是修复工时 |
| **Tripo AI** | 「加工车间」+ 备选生成器 | 已确认（2026-10/11 官方）：分割 Segmentation（语义拆件）+ Part Completion 补面；Smart Mesh 原生四边低模 + 重拓扑 v3.0（可设面数、smart_uv）；智能 UV（重展并映射原贴图/骨骼/动画）；自动绑骨 v3.0——7 种生物类型（双足/四足/六足/八足/鸟类/蛇形/水生）+ others，骨骼规范可选 Mixamo/ActorCore/UE5/VRM/Unity；预设动画库 + 动作重定向（原地模式去根位移）；Text to Motion；材质重贴图/Magic Brush 局部改/PBR/Style Reference；GLB/FBX 导出；API v3 全链路可脚本化。**官方自认的边界**：肩部变形是常见问题、Studio 内不能改骨骼与权重、AI 头发是静态的、重拓扑丢 UV 需重贴图 |
| **Blender** | 唯一装配权威：骨架标准、权重、贴合、动画修整、渲染发布都在这里定版 | 平台产出只进 raw 区，永不直接覆盖已验收母版 |

Tripo 额度量级（Studio 表，核查时）：HD 生成 15 / P1 生成 35 / P2 生成 100 / 重拓扑 10 / UV 20 / 绑骨 20 / 动画 20 / 分割 30 credits；API 表价格不同，不要混算。打法：**先开 1,000–4,000 credits 的试验池**做 M0 对照（同图、同甲片、同烬翼，两平台比「通过验收的总成本 = 扣费 + 修复工时 + 返工」），再决定是否扩量。Rodin 现有余额 40 credits 继续承担主角线。Tripo 免费版模型公开且不可商用，只配试流程；商用验证需 Pro（约 $20/月起，订阅与否 Quinn 拍板）。阿里云百炼已上架 Tripo 全家桶（2026-10），可作国内通道备选。

## 三、标准件先行（量产前必须冻结）

1. **男女标准人体各一副**：一次修好、锁拓扑与静止姿势（A-pose 30–45°、手掌姿态固定、双腿分开）。优先用可控来源（合法基础人体/Blender 修形），AI 只给形体参考——绝不让 AI 每次生成一副「差不多的人体」。肤色/纹样是贴图变体，不是新网格；头部独立、用标准颈圈接缝。
2. **项目骨架规范**：Blender 米制、Z 上、静止朝 -Y、脚底中心为原点。核心骨：root → pelvis → spine_01/02 → chest → neck → head；clavicle→upper_arm→forearm→hand（.L/.R）+ 五指各 3 段；thigh→shin→foot→toe。挂点骨 `socket_weapon.R/L`、`socket_back`、`socket_head` 和发链 `hair_01..`、翅膀附属骨链独立于核心骨。男女共享语义层级，各自一份 rest 骨架；**兼容 = 骨名+父子+rest 矩阵+骨长+轴向+单位全对**，只对骨名不算兼容。平台绑骨（含 Tripo/Rodin）只作初稿，一律转换进项目规范。Rigify 只作操控层，输出用映射好的变形骨。
3. **非人形按「运动结构」分骨架族**：人形语义族（敌人中的类人形）、飞行族（烬翼：主体+翼根/翼段+尾/头，动作 hover/move/attack/hit/fall）、巨型/多足/蛇形各自成族。两种生物「都能自动绑」不构成共用骨架的理由。
4. **动画库按角色裁剪**（30fps 母版，渲染采样 12fps、快攻可 24fps；八方向 = 同一条 Action 八次取景，不是八套动画）：idle/战斗 idle、walk/run、attack_01–03（按武器姿态族，命中帧人工定）、hit、death、cast 三段、dodge/skill/interact 按需；NPC 只做 idle/walk/interact；Boss 每只另加 2–4 个机制专用动作。命中/取消/无敌窗口走独立事件表（按秒），不绑渲染帧。

## 四、单件生产流程（12 步，每步有验收门）

1. **设定冻结**：正/侧/背多视图 + 色板 + 材质块 + 比例尺，同一姿态；背面不靠生成时猜；武器单独出图。脸与马尾有身份标记。不合格不进入生成。
2. **生成候选**：Rodin 主线、Tripo 对照，2–4 个候选封顶。先看游戏相机角度的剪影再看特写；手指、腋窝、背部无不可修的融合。**两轮还不行就改输入图或转手工，停止抽卡。**
3. **下载留档**：task ID、设置、原包、hash、费用记入台账；ZIP 能解压重开才算交付。
4. **清理/拓扑**：保留高模，另做可变形母版。肩肘髋膝有可控环线，无内壳/反法线；身体建议 15k–40k 三角面，衣装整体 10k–40k，Boss 单独评估。Tripo Smart Mesh/重拓扑可出候选，环线不合格照样回 Blender。
5. **UV/材质**：共用件 UV 冻结不变；贴图密度一致、头脸优先；默认 1K/2K，主角特写 4K；底色去掉烘进贴图的冲突光照，粗糙度统一范围。七系列小件 = 同模型换材质，严禁用整身重贴图换系列（会漂移身份）。
6. **绑定**：把网格绑到项目骨架规范（不是平台每次新生成的骨架）。
7. **权重/变形验收**：压力姿态全套（抬臂、抱胸、举刀、蹲、跨步、扭腰、倒地）无塌肩、无腿粘连；权重 normalize、清微权重、每点影响 ≤4。
8. **动画适配**：同族动作重定向后修脚滑与握持；攻击节奏与命中帧人工定版。
9. **零件适配**（仅换装角色）：贴合（贴身件从标准人体表面提衣片、挤厚建模为首选；体积件单独生成后清理内腔再贴合；分割只作提取加速器——它只能分出已有表面，补不出被遮挡的人体与衣服内侧）；从人体/专用笼 Data Transfer 传权重（Nearest Face Interpolated、左右分区）；标准身体按部位做 mask，外观组合隐藏被可靠覆盖的身体面（领口袖口靴口留重叠圈）；贴身布料间隙起点 3–8mm、硬甲 10–20mm（按 1.7m 体型），最终以全动作八方向接触表验收。武器统一握把坐标 + grip offset；头盔配头发可见性掩码/戴盔发型，马尾保留。马尾做 3–6 段骨链手调、物理只作离线辅助并烘焙成确定动画——八方向共用同一缓存，禁止逐方向重模拟。
10. **八方向分层渲染**：Blender 固定版本 + Python 批处理（见第五节规范）。
11. **图集与 Godot 接入**：一个动画时钟驱动全部层（action+direction+t 算帧同步赋帧），换装不重启动作时间；判定走玩法数据不用图片包围盒；按角色/装备/动作分组加载。
12. **母版发布**：资产目录固定结构 `source/ master/ render/ game/ qa/`；新机器断网能打开、装配、重渲染才算发布。

## 五、渲染与合成规范（本管线最容易低估的一节）

- **摄影棚冻结**：正交相机，俯角首测 35°（对照 30°/40° 后冻结）；固定正交范围、灯光、色彩管理、曝光；全员共享像素/米（普通人形先试 256×256 画布、屏幕身高约 140–180px），Boss 扩画布不缩比例。角色绕原点逐次转 45° 取八向，dir 0–7 = S/SW/W/NW/N/NE/E/SE，出标定图核对旋转正负；灯光留在世界空间。
- **遮挡方案：B 档已定（2026-11-11 Quinn 拍板）**：各槽独立分层渲染 RGBA + 深度，Godot 自定义 shader 逐像素按深度合成，实现视觉任意混搭。硬性要求：全层同一相机、同一深度范围与解码；半透明羽毛/发丝的单深度排序不可靠，优先风格化实体发束与不透明羽片，透明材质受限使用并单独测试；深度图禁止缩放后直接比较（精度会坏）；跨层阴影/AO 受限（柔和固定照明 + 地面阴影独立层），全装 Beauty 图只作对照验收。**M1 的核心验证项就是这条合成链**：深度精度、透明边、目标设备 shader 性能与显存预算，全部实测过关才扩产。
  - A 档（受控外观包 + 前后片）保留为降级预案：若 B 档在 M1 验证不过关，退回 A 档保上线，B 档继续迭代。
- **锚点契约**：同一 Action 一次求值、同帧所有层从同一场景渲染；默认整画布不裁切（裁切必须保留 trim_offset 以 pivot 复位）；图集不旋转打包，边缘扩色 2–4px；alpha 约定（straight/premultiplied）Blender 与 Godot 统一，黑白底查边；循环动作输出 [0,T) 不重复首尾帧。
- **体量红线**：一个人形约 100 帧核心动作 × 8 向 = 800 张/层，256² RGBA 约 200MiB/层未压缩——**按帧像素算账，不按模型数**。分组驻留 + 目标平台压缩格式 + 目标设备实测，不过预算先降画布/动作重复度，不先砍验收。
- manifest 必备字段：asset_id、body_type、rig_version、action_version、look_version、camera_version、equipment_compatibility、direction_map、fps、frame_count、loop、pivot_px、canvas_size、trim_offset、layer_schema、event_times、source_hash。

## 六、排期、成本与里程碑（Codex 估算，熟练人员有效工时）

- 单角色：常规人形 24–49h；主角（身份+马尾+首套换装）40–80h；独特 Boss 48–96h；NPC 12–24h。大件平均 4–10h/件（武器 2–5h、复杂长袍 12–20h）；35 件只适配女体 140–350h，全适配男体另加 70–175h（不必重生成）。
- 总基线（14 角色 + 35 大件 + 男女标准体 + 动画库 + 管线基建）：916–1,742h，加 25% 返工 ≈ **1,145–2,180h（143–273 人日）**。传说件另按 8–20h/件追加。这是「做到可商用」的真实账，生成本身只占其中很小一块。
- **里程碑先证伪最难的**：
  - M0（2–3 人日）：冻结女体、相机、像素尺寸与绯隼身份；Rodin/Tripo 同图对照 + 下载可靠性验证；产出费用/修复台账。
  - M1（8–12 人日，另加深度合成原型工时）：绯隼 + 烬翼（故意选最难的非人形）全闭环进 Godot：idle/run/attack/hit/death、剑 + 长武器、衣裤靴两组、r2/r3/六翼代理；验收 = 最极端动作无明显穿模、**B 档深度合成在真实混搭组合下遮挡正确（武器穿身、马尾与翅膀交叠、半透明边）**、换装不停表、目标同屏数下内存与帧时达标。B 档不过关则触发 A 档降级预案，不硬扛。
  - M2（5–8 人日）：男女标准体、完整人形动作族、七系列中两套正式大件、一个大型 Boss 灰盒；冻结全部接口与 schema。
  - M3：每批 2–3 角色/一系列大件量产，每批过自动检查 + 接触表，禁止攒到最后才进引擎。
  - M4：全量组合回归、特写、加载、备份收口。

## 七、风险与停止规则（摘录，全表见讨论稿第 8 节）

- 身份漂移：身份图/头部母版锁定；衣服的输入图去掉脸；不把「全身重生」当换装手段。
- 分割拆不出衣服：标准人体独立存在，贴身衣从标准人体建；两轮拆分仍需大补 → 直接重建，不恋战。
- 自动权重翻车：压力姿态验收是硬门，「静态看不出」不算通过。
- 层序翻车：M1 用像素遮挡方案验证，禁止靠固定 z 序掩盖。
- 平台故障/涨价/改版：完成即下载留档；规范只认 Blender 里的项目标准，平台更新不自动替换已发布资产；费用台账跟资产走。
- 返工熔断：单件两轮候选或修复工时超过同类手工预估 → 停抽卡，改输入或从标准体建模。
- 商用合规：保存平台条款、订阅与导出凭证、第三方动作来源；「能下载」≠「可发布」。
