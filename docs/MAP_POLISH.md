## 第 1 轮（2026-11-06，Quinn 22:31 反馈）：隐形墙、躺着的元素

### 1. 隐形墙

**复现**：新写的地图诊断 `mapdiag.js`——整张地图逐块渲染拼成一张，再把每 8 像素一格「为什么走不了」标上颜色（地图边 / 地标底座 / 散件碰撞 / NPC / 未解锁封印 / 「会被盖住」），最后从守灯驿门口泛洪出可达区。

| | 子轮 A 以后（v41） | 本轮以后 |
|---|---|---|
| 能走的格子 | 32 435 | **41 156** |
| 被「会被盖住」规则挡住的格子（隐形墙） | **9 181** | 0 |
| 散件碰撞挡住的格子 | 1 095 | 787 |
| 看着空、却从营地走不到的格子 | 125 | **0** |

**根因（验证过，不是猜的）**：主因是子轮 A 的「防遮挡」被写成了「禁行」：`blocked() = solid() || hiddenAt() > 0.36`——凡是站上去会被前景像素盖住超过 36% 的点都走不了。树冠、灯柱、石拱、地标的整片图都会盖住人，于是视觉上的空地被封死：树占了约 2 400 格（树冠整片）、练剑场 1 010、每个地标周围 600 左右、石拱 364、芦苇 152、灯柱 97（每根灯柱一道竖条）。
次因：散件碰撞是按种类写死的圆 / 椭圆（`PROP_BLOCK`），和素材的底座对不上——石头的圆比画出来的石头还小（人会走进石头里），石拱的椭圆把门洞也挡了，灯柱 r = 5 倒是不大。

**改法**：
1. **遮挡和碰撞分开**：`blocked()` 只看实际的底座；会被盖住时只在最上层补画半透明剪影（已有的 ghost，盖住超过 12% 就画），不再禁行。NPC 身后那一段「防遮挡」的挡路也去掉。
2. **散件的底座按素材量**：每件散件在素材里贴地那一段（树和灯柱量 30～50 像素高处的树干 / 灯杆，其余量离地 4～16 像素），只算「实心」的列（八成以上不透明，稀疏的草叶不算），连成几段，每段一个扁椭圆。结果：灯柱的底座约 10 像素宽；树只挡树干；石拱量出两根柱子、中间的门洞能走；断墙、石头按实际宽度挡。灌木、芦苇不挡路。
3. **地标的底座按素材补齐**：原来每个地标只有一个椭圆，和建筑对不上。补了几块（`SITES[].feet`）：墓穴的建筑本体和两侧围栏、守灯驿前面的两段木栅栏、练剑场的围场。
4. **抽查**：每对相邻（260 像素以内）的灯柱之间、每个石拱的门洞中间都能走、从营地走得到（全部通过）；7 个入口全部「走进去 → 弹出卡片」。

对照图：`mapdiag_before.png`（红 = 隐形墙）/ `mapdiag_after2.png`（只剩橙色的真实底座和紫色的地标底座）。

### 下一轮起的候选精修点（每轮挑几项，先列再做）

- 植被密度和分布：空旷处偏单调、局部扎堆；
- 道路边缘：石路和荒原的过渡偏生硬；
- 物件错位：个别散件压在道路上、离地标太近；
- 光影一致性：地标自带的光影方向和引擎的灯光（烽灯、长明灯塔）对不齐；
- 地图边缘：左右两侧的断崖素材有一段看起来像黑洞。
