## 一、槽位与数据模型

### 1. 槽位清单（定稿）

|---|---|---|---|---|
| `weapon` | 武器 | 攻击力（+太刀暴击） | ✓ 刀光颜色 + 元素刀光 | 长剑 / 太刀 / 巨剑，流派特性照旧 |
| `helm` | 头盔 | 防御、生命 | 立绘 | |
| `chest` | 胸甲 | 防御、生命 | 立绘 | 旧 `armor` 改名迁移 |
| `legs` | 护腿 | 防御、生命 | 立绘 | **新** |
| `boots` | 战靴 | 防御、生命 | 立绘 | **新** |

| `wings` | 翅膀 | **固定攻击 +10**（所有翅膀一样） | ✓ 背层动画 | **新**。稀有度只决定动画、美观和手感，数值零差异（见第 3 条） |

**皮肤不是一个槽位**，而是每个槽位上的一层「外观覆盖」（第 5 条）：皮肤只换样子、永远不带属性。这样职业和皮肤都不需要再改槽位结构。

### 2. 两层数据：装备定义（目录）+ 装备实例（存档）

**装备定义 `ItemDef`**：静态目录，一件「装备」= 一条定义。加装备只加数据、不改代码。

```js
// src/gear/catalog.js（由规则表展开 + 传说手写表合成，见第二节）
{
  id: 'sword_frost_r2',      // 唯一 id，命名规则见第二节第 4 条
  slot: 'weapon',            // 槽位（饰品写 'trinket'，穿到 trinket1 / trinket2 都行）
  kind: 'sword',             // 款式：sword / katana / great / helm / chest / legs / boots / bracers / ring / amulet / wings / veil
  series: 'frost',           // 主题系列（决定元素、配色、纹样、套装）
  rar: 2,                    // 稀有度 0～4：普通 / 精良 / 稀有 / 史诗 / 传说（固定在定义上）
  name: '霜烬·纹刃',
  art: { icon: 'sword_frost_r2', portrait: 'sword_frost_r2', battle: null }, // 外观引用：图集里的 key
  effects: [],               // 固定效果（传说 / 套装件才有）；随机部分在实例上
  imbue: 'chill',            // 状态词条的元素（稀有及以上才生效，见第三节）
  set: 'frost',              // 套装标签（null = 不属于套装）
  classReq: null,            // 职业限制（预留）：null = 通用
  pvp: false,                // PVP 白名单（预留）：本期一律不进场
  drop: { stages: [1, 2], weight: 1, boss: null }, // 掉落来源
}
```

**装备实例 `Item`**：存档里的一条，只记「这一件」随机出来的部分。

```js
{
  uid: 'lq3k…',              // 实例 id（沿用 newId）
  def: 'sword_frost_r2',     // 指向目录
  ilvl: 12,                  // 物品等级：决定基础属性和词条数值
  enh: 3,                    // 强化
  affix: [{ k: 'crit', v: 0.03 }],   // 随机数值词条（沿用）
  mark: 'counter',           // 刻印（沿用，可铭刻覆盖）
  imbueLv: 2,                // 状态词条的强度档 1～3（稀有 1～2、史诗 2～3、传说 3）
  reforged: 1, locked: false,
  skin: null,                // 外观覆盖（预留）：皮肤定义 id
}
```

稀有度和名字都在定义上，不再随机抽名字。这样「几百件装备」每一件都是一个能被收集、能被认出来的东西，而不是同一件装备换了数字。

### 3. 数值预算：槽位变多，总强度不变

槽位从 4 个变成 10 个。如果每个槽都按旧标准给属性，战力会翻倍，首领动态难度和关卡平衡会一起崩。规则：**把旧四个部位的总预算拆到新槽位里，总和不变**。

基础属性（L = 物品等级，最后再乘稀有度倍率）：

| 槽位 | 防御 | 生命 | 攻击 | 暴击 |
|---|---|---|---|---|
| 武器 | — | — | 8 + 3.2L（× 流派倍率，同旧） | 太刀 +4%（同旧） |
| 胸甲 | 3 + 1.2L | 12 + 6L | — | — |
| 头盔 | 1.5 + 0.6L | 6 + 3.5L | — | — |
| 护腿 | 2 + 0.8L | 7 + 3.5L | — | — |
| 战靴 | 1.5 + 0.6L | 5 + 3L | — | — |
| 护腕 | — | — | 1 + 0.4L | — |
| 饰品 ×2（每件） | — | — | 1 + 0.4L | 0.5% |
| 翅膀 / 光幕（每件） | — | — | **固定 10**（不随等级、稀有度变） | — |
| **合计（非武器）** | **8 + 3.2L** | **30 + 16L** | **3 + 1.2L** | **1%** |
| 旧：头盔 + 护甲 + 戒指 | 8 + 3.2L | 30 + 16L | 3 + 1.2L | 1% |

随机词条的数值按槽位乘一个份额：武器 1.0、胸甲 1.0、头盔 0.5、护腿 0.5、战靴 0.4、护腕 0.4、饰品各 0.45。份额总和是 4.7，旧的是 4.0。多出的约 17% 正好对应新加的「史诗」档，由 `REF_POWER` 重算吸收（第三节第 7 条）。

**翅膀和光幕：一律固定攻击 +10，稀有度 = 纯外观与手感**（Quinn 2026-11-09 13:46，覆盖原稿「不带数值、只带效果」）。
- 不分品质、系列、稀有度，每件翅膀 / 光幕都只给攻击 +10。目录里 wings / veil 的属性写死 `atk: 10`，不乘稀有度倍率，不随物品等级变。
- 没有随机词条、刻印、状态词条；不能强化、不能重铸、不能传承；**不计入套装件数，也不算搭配效果的状态来源**。不然稀有度或系列就会通过套装 / 搭配间接带来强度差。
- 稀有度只体现在三处：**动态效果、美观、手感**（第六节 E5 的分档表）。这是「我们不是卖数值的」的直接体现：橙色翅膀比白色翅膀好看、动起来更舒服，但打人一样疼。
- 数值影响（实测，按同级精良装备的攻击估算）：两件合计 +20 攻击，在 1 级约 +68%、5 级约 +26%、10 级约 +15%、30 级约 +5%。前期占比很大，所以：
  - 第一对翅膀 / 第一道光幕从第 2 关首领起才会掉（约 4～6 级，那时约 +25～30%）；
  - `REF_POWER` 重算时把这 +20 算进去，首领动态难度会跟上。
  - 「固定 +10」这条规则本身不动。

稀有度（新增「史诗」插在稀有和传说之间）：

| 档 | 名称 | 颜色 | 基础属性倍率 | 随机词条 | 状态词条 | 掉落权重（第 1 关起，随关卡往高档偏） |
|---|---|---|---|---|---|---|
| 0 | 普通 | `#d8d3c8` | 1.00 | 0 | — | 58 |
| 1 | 精良 | `#4fa3ff` | 1.15 | 1 | — | 27 |
| 2 | 稀有 | `#b46bff` | 1.30 | 2 | 1 条，强度 1～2 档 | 10 |
| 3 | 史诗 | `#ff5aa0` | 1.42 | 2 | 1 条，强度 2～3 档 | 4 |
| 4 | 传说 | `#ff9a2e` | 1.55 | 3 | 1 条，强度 3 档 + 固定专属效果 | 1（只在首领 / 试炼 / 指定来源掉，有保底） |

刻印照旧：稀有 40% 带一条，史诗 70%，传说必带；刻印石铭刻照旧。

上表的倍率、词条、状态词条、刻印**都不适用于翅膀和光幕**：它们只有固定攻击 +10，稀有度只决定外观和手感（见上一段）。

### 4. 和现有系统的关系（定死：全部收编进一套模型，没有第二套）

| 现有系统 | 处理 | 具体 |
|---|---|---|
| 4 个槽位 | **扩展** | `weapon` / `helm` 不变；`armor` → `chest`；`ring` → `trinket1` |
| 4 档品质 | **扩展为 5 档** | 旧传说 `rar 3` → 新 `rar 4`；新「史诗」= 3 |
| 随机词条 `AFFIX` | **保留**，进实例的 `affix` | 数值按槽位份额缩放；词条池不变 |
| 刻印 `MARKS` | **保留**，进实例的 `mark` | 刻印是「打法条件」（破招后、满血时……），状态是「元素效果」，两条线互不替代。同名刻印照旧不叠加 |
| 强化 | **保留** | 只加成基础属性；翅膀 / 光幕固定攻击 +10，**不能强化**（数值不成长） |
| 重铸 | **保留**，只重铸随机词条 | 状态词条跟系列走，不能重铸：系列身份必须稳定（霜烬就是冰） |
| 传承 | **保留**，按槽位 | 饰品两个槽互相算同部位 |
| 出售 / 锁定 / 整理 | **保留** | 背包上限 40 → 60（槽位多了） |
| 武器流派 | **保留** | 流派由 `kind`（sword / katana / great）决定，和系列无关 |
| `playerLook()` | **改写** | 从装备定义里读外观引用（第四节） |

**旧存档迁移（存档 v1 → v2，一次性、不丢东西）**：
- 每件旧装备按「部位 + 武器类型 + 等级段」映射到新目录的「行者」系列同档定义（旧的 `TIER_NAMES` 名字保留成这个系列的名字，玩家认得出来）。
- 旧传说按名字映射到新目录里对应的独立传说定义（旧 `LEGEND_NAMES` 的 10 个名字都在第二节的传说表里保留）。
- `ilvl` / `enh` / `affix` / `mark` / `locked` / `reforged` 原样搬过去。
- 旧稀有 / 传说装备补一条状态词条：按名字归到最接近的系列，强度取 1 档。旧装备迁移后不会比原来弱。
- 迁移写成纯函数，配一个确定性测试：拿旧存档样本迁移，逐件对比属性不降、件数不变。

### 5. 预留：职业、皮肤、PVP（只留字段，本期不做）

- **职业**：定义上有 `classReq`（null = 通用）和槽位 `class`。职业上线时：职业专属武器、职业槽的效果都只是目录里多出来的数据；职业也可以给某个元素加成（「火系专精」），走第三节的同一套状态表。
- **皮肤**：实例上有 `skin`，存档另有 `save.skins`（拥有的皮肤）。皮肤定义 = 只有 `art` 的装备定义，`effects` 必须为空，构建工具会拦。整套换装的图集路线（第四节路线 B）就是皮肤系统的素材路线。
- **PVP**：按既定规则「场外装备不进场」。定义上有 `pvp`（默认 false）；以后加一个 `ruleset.gear = 'off' | 'whitelist'`，在 `computeStats()` 和状态系统的入口统一判断。本期不实现。

| 腐沼 | 中毒持续 +2 秒 | 中毒 ≥ 6 层的敌人受到你的技能伤害 +15% |
| 血棘 | 流血每跳 +20% | 浮空 / 撞墙时流血额外结算一跳，并回复本次伤害的 30% |
| 晨辉 | 护盾值 +25% | 护盾被打破时触发一次净化，并对周围敌人造成一次光爆 |

行者没有套装。套装件数按「同系列件数」数，跨稀有度也算（穿一件普通霜烬护腿也算一件）：让低稀有度装备在凑套装时仍有用处。**翅膀和光幕不计入套装件数**（第一节第 3 条）。

### 3. 素材生成策略（每件都是真造型；不许同形换色）

> **2026-11-09 改版**（消息 29，质量铁律）：原稿的「48 个基础款式 × 系列配色 + 纹样」合成，本质是同一个造型在 6 个系列之间换颜色，**作废**。现在的规则：保底的 308 个格子**每一格都是单独设计、单独画的造型**；构建时只合成稀有度底板，不再给装备本体染色。

**图标是必须项**（透明底，交付 256×256，游戏里显示 64 / 详情页 128～192）。

**造型怎么区分**（验收逐项查，见第八节第 0 条）：
- **系列之间**：靠「造型母题 + 纹样 + 配色」三者一起区分，**造型母题是第一位的**。同一个款式（比如战靴）在 6 个系列里必须是 6 种不同的结构：
  - 霜烬：冰棱、尖晶、层叠的霜片；
  - 燎原：火舌形的护片、烧焦卷边、余烬镶嵌；
  - 惊雷：折线鳍片、导电的金属线圈、分叉的尖角；
  - 腐沼：缠绕的藤、鼓起的囊泡、锈蚀的孔洞；
  - 血棘：荆棘缠绕、倒刺、缝合的皮革；
  - 晨辉：日轮圆盘、放射的羽状饰片、光滑的白金曲面。
- **档位之间**：普通 → 史诗是**造型本身的升级**：轮廓更复杂、结构件更多、装饰件更多（护片、垂饰、镶嵌、披挂），不是同一个形加光。
- **变体之间**：同一格子的 `_v2`、`_v3` 也必须是轮廓或结构不同的造型，不是同形换色。

**构建时合成的只有**：稀有度底板 `frame/r{0-4}`（图标背后的一块底，所有装备共用）。史诗 / 传说的光效画进各自的图标里，不用通用装饰层。

素材数量（保底）：

| 类别 | 数量 |
|---|---|
| 行者系列（10 款 × 2 档） | 20 张 |
| 6 个元素系列（12 款 × 4 档） | 288 张 |
| 传说定制 | 36 张 |
| 稀有度底板 | 5 张 |
| **合计** | **349 张**；变体另计，不封顶 |

### 4. 命名规则

- **id**：普通件 `{kind}_{series}_r{rar}`（如 `boots_ember_r3`）；传说 `lg_{来源}_{kind}`（如 `lg_ironjaw_great`）或 `lg_{拼音名}`（如 `lg_duanyue`）。
- **素材文件**：`icons/{id}.png`（每件一张，含传说和变体）、`frame/r{0-4}.png`（稀有度底板）。
- **中文名**：`系列名·档位名`。档位名按款式查表（每款 4 个，普通 → 史诗由朴到雅）。例：长剑「铁剑 / 钢剑 / 纹刃 / 名锋」→「霜烬·纹刃」；护腕「布缠 / 皮护腕 / 刻纹护腕 / 镇魂护腕」→「血棘·刻纹护腕」。行者系列直接用旧 `TIER_NAMES` 的名字。四十多个档位名在实现时一次写进表里。

## 三、Buff 系统与相互作用

### 1. 状态清单（定稿：12 种）

在 Muse 列的 11 种基础上：「冰冻」拆成「寒意（积累）→ 冻结（触发）」，「麻痹」拆成「感电 → 麻痹」，避免一刀冻住的数值碾压；新增组合产物「脆化」，它只能由相互作用产生，不能直接施加。

**施加给敌人（负面）**：

| key | 名称 | 类型 | 规则 | 叠加 |
|---|---|---|---|---|
| `burn` | 灼烧 | 持续伤害 | 每 0.5 秒造成「施加时攻击力 × 2%」× 层数，持续 4 秒 | 最多 5 层；再次施加 +1 层并刷新持续时间 |
| `poison` | 中毒 | 持续伤害 | 每 0.5 秒 1% × 层数，持续 6 秒；**中毒者受到的治疗 -50%**（司祭的治疗被克制） | 最多 10 层；+1 层并刷新 |
| `bleed` | 流血 | 持续伤害 | 每 0.5 秒 1.5% × 层数，持续 5 秒；**目标被击飞 / 撞墙 / 被拖拽时额外结算一跳**（和浮空连、推墙的玩法挂钩） | 最多 5 层；+1 层并刷新 |
| `chill` | 寒意 | 积累 | 积累值 0～100%，满了触发「冻结」；寒意期间移速 -20%（减速包含在内）；3 秒不再积累就开始衰减 | 积累值累加 |
| `freeze` | 冻结 | 控制 | 普通敌人 1.2 秒、精英 0.6 秒完全定住（不受击退，受伤 +10%）；首领不冻结，改为「霜蚀」：霸体条立即削 15% | 触发后同一目标 8 秒内冻结阈值 ×1.5（控制递减） |
| `shock` | 感电 | 积累 | 积累值 0～100%，满了触发「麻痹」 | 积累值累加 |
| `paralyze` | 麻痹 | 控制 | 0.8 秒；**打断当前出招**（判定等同破招，但不给破招奖励）；首领不麻痹，改为读条打断值 +3、当前出招前摇变慢 20% | 同冻结的控制递减 |
| `slow` | 减速 | 削弱 | 移速和出招速度 -15%，3 秒 | 不叠加，取最高值、刷新时间 |
| `brittle` | 脆化 | 削弱（只能由相互作用产生） | 受到所有伤害 +20%，4 秒 | 不叠加，刷新时间；脆化期间不能再被冻结（防止冻住打碎再冻住的无限连） |

**施加给自己（正面）**：

| key | 名称 | 触发 | 规则 | 叠加 |
|---|---|---|---|---|
| `fury` | 战意（攻击提升） | 事件：破招 / 弹刀 / 连击每满 20 下 | 攻击力 +6% / 层，6 秒 | 最多 3 层；+1 层并刷新 |
| `shield` | 护盾 | 事件或常驻回复（看装备） | 吸收伤害，值 = 最大生命 × 装备给的比例；**先吸收持续伤害**；5 秒没受伤后护盾慢慢回复（有回复效果的装备才回复） | 值累加，上限为最大生命 × 30% |
| `lifesteal` | 吸血 | 常驻 | 造成伤害的 x% 转为生命；每秒最多回复最大生命 2%（防止巨剑技能一刀回满） | 装备之间累加，总上限 8% |
| `thorns` | 荆棘 | 被近战命中 | 反弹「本次受到伤害 × x%」给攻击者（不受防御影响，不会暴击） | 累加，总上限 60% |
| `cleanse` | 净化 | 事件：极限闪避，或带净化的装备每 12 秒一次 | 清除自己身上全部负面状态 | — |

**敌人对你施加的状态**（Quinn 已定本期开）：只开这几个来源，让净化、护盾有用处：祭坛火焰 → 灼烧、腐化司祭的诅咒 → 中毒、屠夫 / 铁颚的斧伤 → 流血；其余敌人不加。这部分改了敌人的玩法，作为状态模块里的一个子工单，和装备的状态一起上线。

### 2. 相互作用矩阵（写死）

规则读法：**目标身上已经有「行」的状态时，又挂上「列」的状态**会发生什么。表格对称的地方只写一处。空格 = 互不影响，各算各的。

| 已有 \ 新挂 | 灼烧 | 中毒 | 流血 | 寒意 / 冻结 | 感电 / 麻痹 | 减速 |
|---|---|---|---|---|---|---|
| **灼烧** | 叠层 | **毒爆**（增强） | **灼口**（抵消） | **融化**（抵消 + 爆发） | | |
| **中毒** | 毒爆 | 叠层 | **毒血**（增强） | | | |
| **流血** | 灼口 | 毒血 | 叠层 | **凝血**（抵消） | | |
| **寒意 / 冻结** | 融化 | | 凝血 | 积累 | **碎冰**（增强 → 脆化） | **冻僵**（增强） |
| **感电 / 麻痹** | | | | 碎冰 | 积累 | |
| **减速** | | | | 冻僵 | | 取最高 |

**反应的定义**：

| 反应 | 条件 | 效果 |
|---|---|---|
| **融化** | 灼烧 × 寒意 / 冻结 | 两者**同时清除**（冻结立即解除），爆发伤害 =（灼烧剩余的全部跳伤）× 1.5 +（寒意比例 × 攻击力 × 40%），并向周围半径 90 喷蒸汽，每个敌人受这次伤害的 50% |
| **毒爆** | 中毒 × 灼烧 | **消耗全部中毒层**，爆炸伤害 = 剩余毒伤 × 1.2，半径 120；周围敌人各获得 2 层中毒；灼烧保留 |
| **碎冰** | 冻结 × 感电（或麻痹 × 寒意满） | 冻结立即结束，造成碎冰伤害（攻击力 × 60%），挂**脆化** 4 秒 |
| **毒血** | 中毒 × 流血 | 流血每跳伤害 +30%（两者都在时持续生效） |
| **灼口** | 流血 × 灼烧 | 灼烧把流血**烧止**：每清掉 1 层流血，灼烧 +1 层（不超过上限） |
| **凝血** | 流血 × 寒意 / 冻结 | 冻结期间流血**暂停**（不掉层也不跳伤），冻结结束后恢复 |
| **冻僵** | 减速 × 寒意 | 寒意积累速度 ×1.3 |

**你自己身上的相互作用**：

| 组合 | 效果 |
|---|---|
| 护盾 × 持续伤害（灼烧 / 中毒 / 流血） | 护盾**先吸收**持续伤害；有护盾时灼烧不叠新层 |
| 净化 × 护盾 | 净化清掉的每 1 层负面状态，转成最大生命 2% 的护盾 |
| 中毒（自身）× 吸血 | 吸血效果减半（和敌人受治疗 -50% 同一条规则） |
| 荆棘 × 流血 | 荆棘反伤时给攻击者挂 1 层流血（血棘系列的核心） |
| 战意 × 你施加的持续伤害 | 持续伤害按「施加时」的攻击力快照，战意期间挂上的灼烧 / 中毒 / 流血更痛 |

**防滥用（写死）**：
- 同一目标 1.5 秒内最多触发 1 次反应（反应冷却），避免一刀多重爆炸。
- 冻结 / 麻痹有控制递减（上表）；首领永远不会被硬控。
- 反应伤害和持续伤害**不算连击数、不加风格分、不造成硬直和击退**（不让挂毒挂火替代动作操作）；但击杀照常算。

### 3. 怎么进战斗结算

新建 `src/status.js`（数据表 `STATUS`、`REACTIONS` 在顶部，后面是引擎），四种触发方式：

| 触发 | 挂在哪 | 用于 |
|---|---|---|
| **命中附加** | `applyHit()` 命中成立之后 | 状态词条：按招式级别给积累 / 层数 |
| **被击触发** | 主角受伤处理 | 荆棘、受击护盾、反击类 |
| **常驻** | `computeStats()` | 吸血比例、护盾上限、元素加成（套装） |
| **事件** | 现有的破招 / 极限闪避 / 弹刀 / 撞墙 / 连击计数钩子（刻印已经在用这些钩子） | 战意、净化、套装 4 件 |

**积累模型（不掷骰子）**：每次命中给的量 = 招式级别 × 状态词条强度。级别：普攻 1、重击 / 上挑 2、技能 3、必杀 5。强度：1 档 = 6、2 档 = 9、3 档 = 12，单位是「层」用于持续伤害、「%」用于积累。

举例：2 档寒意的武器，普攻每下 +9% 寒意，技能 +27%，大约一套连段冻住一个普通敌人。没有触发概率，打多少就积累多少，玩家能预期，靠操作打出来。

**多件装备同元素**：强度相加后按 √ 递减，同一元素总强度上限是 1 档的 3 倍，不能堆一身同元素把敌人冻成雕像。

**持续伤害的结算**：
- 每 0.5 秒跳一次。
- 按施加时快照的攻击力算，不暴击。
- 对敌人：照常吃敌人减伤，但跳伤不触发受击硬直、不打断出招。
- 对主角：无视防御，可以被护盾吸收。
- 跳伤数字用状态色的小号字，不刷屏（同目标同状态 0.5 秒合并一个数字）。

**敌人抗性（让 buff 成为应对关卡的选择）**：每种敌人一行抗性表（`ai_data.js` 旁边的数据），0 = 正常、0.5 = 减半、1 = 免疫。例：
- 骨兵类不流血、怕灼烧（流血 1 / 灼烧 -0.3）；
- 烬翼免疫灼烧；
- 屠夫中毒抗性 0.5；
- 首领统一：持续伤害抗性 0.3，控制只走「霜蚀 / 读条打断值」替代效果。

每关的推荐元素写在关卡卡片上（「此地骸骨不流血」）。

**和现有系统的兼容**：

| 系统 | 兼容方式 |
|---|---|
| 敌人 AI（`ai.js`） | 冻结 / 麻痹期间敌人进入「受控」状态，等同现有的硬直处理：释放进攻名额（`attackers`），读条 / 出招中断；减速乘到移动和出招计时上 |
| 破招 | 麻痹打断出招时**不算破招**（不给破招的暴击、风格分和刻印「断势」），破招仍是靠操作打出来的奖励 |
| 坚盾 / 屠夫格挡 | 被格挡的攻击**不积累**状态（不给绕过格挡的捷径） |
| 首领读条 | 感电满了 → 读条打断值 +3：给「打断读条」多一条元素路线，但仍需要打 |
| 首领动态难度（`boss_scale.js`） | ① `REF_POWER` 按新槽位、新稀有度重算（脚本同第 12 项，200 套随机同级精良装备）；② `power()` 加「状态评分」：每条状态词条按强度档折算固定战力，套装 4 件再加一档。这样穿满元素装的玩家，首领照样跟着强化；首领伤害仍然不加（第 12 项的原则不变） |
| 难度（`D`） | 高难度敌人抗性整体 +0.15；控制递减更快 |
| 训练场 | 木桩显示身上的状态和反应名字，方便试装备 |

### 4. 「不卖数值」落在哪里

- 获取：只从掉落、首领、试炼、委托来；传说有保底计数（同一关首领连续 N 次没掉，下次必掉）。没有任何付费入口。皮肤以后即使上架，也只换样子（构建工具拦截带效果的皮肤定义）。
- 强度：总预算和旧系统相同；状态有上限、有递减、首领不能硬控；反应不加连击和风格分，动作操作仍是核心。
- PVP：场外装备不进场，数据里只留开关。

## 四、上身展示：三条路线的诚实评估

### 1. 先说清楚限制

绯隼是**整张烘焙的序列帧**：26 个动作、149 帧、每帧 256 像素格子，游戏里约 96 逻辑像素高。没有骨骼，也没有部件分层。任何「换上身」都只有三种办法：

1. 在烘焙图外面**叠一层**：只适合轮廓外的东西，比如背后的翅膀、全身的光效。
2. **整张重画**：每套外观重画全部 149 帧。
3. **把主角拆成部件重做**：纸娃娃。

另外，游戏里的主角只有约 96 像素高，裤子、鞋子、护腕在战斗画面里本来就只有几个像素。战斗里真正看得出来的是**轮廓（翅膀）、发光（光幕、刀光）和颜色**。

### 2. 逐槽评估

| 槽位 | 能不能叠层上身 | 成本 | 战斗里的可见度 |
|---|---|---|---|
| 翅膀 | **能**：背层，每帧一个背部挂点 + 角度 | 中：149 帧的挂点可以用工具从剪影半自动标出（脊柱上端），再人工校；每种翅膀 1 组 8 帧扇动循环 | 高（改变轮廓） |
| 光幕 | **能**：前景 + 背景两层全身光效，跟随主角中心，不需要逐帧挂点 | 低 | 高 |
| 武器 | **部分能**：刀光颜色、元素刀光条带、挥刀时的元素粒子都能换；**刀的形状**烘焙在手里，换形状要逐帧标手部挂点 + 角度 + 遮挡顺序 | 刀光：低；换刀形：高 | 刀光高，刀形低（96 像素下刀只有几十像素） |
| 护腕 | 技术上能（逐帧手腕挂点 × 2） | 高（149 帧 × 2 个挂点 + 遮挡） | **很低**（几个像素） |
| 头盔 | 勉强（头部挂点，但会和头发、动作冲突） | 中高 | 低 |
| 胸甲 / 护腿 / 战靴 | **不能叠层**：改变身体轮廓，必须重画 | 只能走 B 或 C | 低 |

### 3. 三条路线

| | A. 立绘换装 + 可叠加槽位真上身 | B. 按系列生成整套换装图集 | C. 现在就改分层纸娃娃 |

4. 风险可控：A 唯一的高风险点是立绘部件对齐，靠「先交底身 + 参考线、每批先预览」控制。

## 八、给 Codex 的素材框架与接口（放量做，按这里交）

这一节是 Codex 发挥的边界：**骨架、接口、视觉语义、验收**由这里定；**款式长什么样、出多少**由 Codex 发挥。

### 0. 质量铁律（Quinn 2026-11-09，和第 14 项同级）

「特效要真特效、真 CG，不是只换个颜色。」验收逐项查，**同形换色的交付直接打回**：

- **状态特效 / 反应**：每一种都是独立的造型和动态设计：形状不同、运动方式不同、粒子行为不同。禁止拿同一套火苗 / 光圈 / 粒子换颜色充当另一种状态。
- **装备造型**：档位和变体必须是造型本身的变化（轮廓、结构、装饰件）；系列之间靠「造型母题 + 纹样 + 配色」三者区分，造型母题第一位，不能只靠染色。
- **翅膀 / 光幕 / 元素刀光**：每一组都是单独的造型和动态，不是一个形换色。
- 引擎染色（灰度发光素材由引擎上色）仍然是允许的**技术手段**，但只能用在「本来就不同的造型」上，不能用来制造「不同的东西」。

验收方法：每批预览都要包含一张「同类对照图」：同一款式的全部系列 / 档位排在一起；状态特效则是全部状态并排、**去掉颜色看灰度**，形状和动态仍然要一眼分得开。

### 1. 骨架（不能改，改了引擎接不上）

- **槽位**：第一节第 1 条的 10 个槽位。新款式只能挂在已有槽位下。
- **稀有度**：5 档（普通 / 精良 / 稀有 / 史诗 / 传说），颜色见第一节第 3 条，底板和光效颜色必须对得上。
- **武器款式**只有长剑 / 太刀 / 巨剑三种（每种绑一个流派玩法）。新武器类型等于新玩法，要我定；Codex 可以在三种之内出任意多的造型。
- **系列**：已定 7 个（第二节第 1 条）。Codex 可以提新系列，但每个新系列必须绑定状态清单里的一个元素（或「无元素」），我审定后才进表，套装效果由我写。
- **其他款式**：饰品下可以加新子类（耳坠、腰坠、护符……）、翅膀和光幕下任意加新造型，不需要先问。

### 2. 装备素材的交付接口（`afterglow.gearpack.v1`）

zip 根目录平铺：

```
README_zh.md
gear.json                    # 清单，见下
frame/r{0-4}.png             # 稀有度底板（只在 E1 交一次）
icons/{id}.png               # 每件一张完整图标（保底件、变体、传说都在这里）
portrait/{id}.png            # 立绘部件层（E4），和同 id 的图标是同一个造型
battle/{id}/{id}_00.png …    # 战斗内序列帧（翅膀、光幕，E5）
docs/preview.png  docs/contact_sheet.png
```

`gear.json` 每件一条（Codex 写，**名字和设定是提案**，我入库时可以改）：

```json
{ "id": "boots_frost_r2_v2", "slot": "boots", "kind": "boots", "series": "frost", "rar": 2,
  "variantOf": "boots_frost_r2", "name": "霜烬·踏雪靴", "lore": "一句话设定（可选）",
  "icon": "icons/boots_frost_r2_v2.png", "portrait": null, "battle": null }
```

- **id 规则**：保底件 `{kind}_{series}_r{rar}`；同一格子的变体加 `_v2`、`_v3`……；定制套装件 `set_{套装名}_{kind}`；传说 `lg_…`。只允许小写字母、数字、下划线。
- **变体**：`variantOf` 指向同一格子的保底件，属性规则完全一样，只是样子不同（造型不同，见第 0 条）。路线 A 下，身体 / 武器部位的变体要连同立绘部件层一起交，否则穿上后立绘对不上。掉落时同一格子在变体里随机选一个：变体越多，同样的掉落越不重样。
- 数值、效果、套装归属**不写在 gear.json 里**，由我按系列规则生成。素材包只管样子和名字。

### 3. 图标的验收标准

| 项 | 标准 |
|---|---|
| 画布 | 256 × 256，透明底（真 alpha，不是棋盘格），主体居中，四边留 ≥ 16 像素空白 |
| 视角与光 | 统一 3/4 斜侧视角；光源左上；和现有暗黑手绘风一致（参考绯隼立绘与 `docs/ART_FEISUN.md`） |
| 可读性 | 缩到 48 像素时轮廓仍能认出部位；**去色成灰度后**，不同系列、不同档位仍能靠轮廓和结构分开（第 0 条） |
| 稀有度 | 档越高越繁复，但**不靠尺寸**区分（所有图标主体大小相近）；史诗 / 传说的光效只能在画布内，不能贴边被裁 |
| 造型母题 | 每个系列的母题见第二节第 3 条，Codex 可以发挥，但同一系列要统一、不同系列不能撞 |
| 禁止 | 文字、水印、边框（边框由稀有度底板负责）；照搬任何现有游戏的装备设计 |
| 一致性 | 同一系列的所有部位一眼看得出是一套（配色、纹样、造型母题） |

### 4. 状态特效：每个 buff 的视觉语义

每个状态要交 3 样（反应交前 2 样）：
- **持续表现**：挂在目标身上的循环序列帧，8～12 帧，首尾无缝；
- **触发爆发**：施加 / 触发瞬间的一次性序列帧，6～10 帧，最后一帧全透明；
- **HUD 图标**：64 × 64，**带颜色**，敌人血条上和角色页都用。

混合方式沿用 `docs/ART_FX.md` 第三节：发光类（add）只交灰度，引擎按下表的颜色染；实物类（冰壳、荆棘、血滴）普通混合，带颜色交。

## 九、装备强弱比较与推荐（Quinn 2026-11-09 13:44，比较口径定死）

### 1. 「紫装比橙装还强」核查结论：主要是标定失误

用现在的代码模拟（`items.js` 的 `makeItem` / `itemScore`、`progression.js` 的 `power`；每组 4000 对随机装备，稀有 = 紫、传说 = 橙）：

| 情况 | 现在的「▲」分数说紫更强 | 按真实战力紫确实更强 |
|---|---|---|
| 同物品等级、都 +0 | 0～1.4% | **武器 7.7%、头盔约 20%、护甲约 15%、戒指约 18%** |
| 紫 +6、橙 +0（武器，12 级） | **98.3%** | — |
| 橙比紫低 2 个物品等级（6 级） | 武器 44%、护甲 22% | — |

三个原因，前两个是失误，第三个一半是设计一半是失误：

1. **比较时把强化算进去了**（失误）：`itemScore` 用的是带强化的属性。紫 +6 对橙 +0，几乎必然显示紫更强。这正是 Quinn 看到的现象。
2. **打分权重和真实战力对不上**（失误）：`itemScore` 是一组手填权重（暴击 ×300、攻击 ×3……），和 `computeStats` / `power` 的实际收益不一致。刻印完全不计分，传说必带刻印，等于白送的东西没算。结果是分数和真实强弱两头都错。
3. **稀有度之间的差距被随机词条盖过去了**：传说和稀有的基础属性只差 17%（1.55 / 1.32），而词条种类的价值差好几倍（同一条位上抽到攻击 % 和抽到魔力回复差距很大），数值又在 60%～100% 之间随机。所以同等级下紫装靠词条运气赢橙装并不少见。高物品等级的紫装赢低等级的橙装，属于正常设计（物品等级就是成长），但现在界面上没说明原因。

**修标定（进数据模块）**：
- 比较一律用第 2 条的口径，删掉 `itemScore` 的手填权重，改成「换上这件之后真实战力的变化」。
- 词条数值按稀有度给质量系数：精良 0.8、稀有 0.9、史诗 1.0、传说 1.15；随机区间从 60%～100% 收窄到 80%～100%。
- 刻印、状态词条、套装、搭配都折算成战力当量参与比较（第 2 条）。
- **验收标准**（数据模块里加一个确定性的模拟测试，每组 10 000 对）：同物品等级、同强化、不算套装和搭配时，低一档赢高一档的比例 ≤ 5%，低两档（如稀有对传说）≤ 1%。

刻意保留的「低稀有度更强」只有三种，对比里必须写明原因：
- **物品等级更高**：显示「物品等级 +N」；
- **凑套装 / 搭配**：显示「穿上后凑齐霜烬 4 件」或「触发冰火交织」；
- **场景克制**：显示「对骸骨类敌人：流血无效」这类提示，只提示、不进结论。

### 2. 比较口径（定死）

- **同强化折算**：未穿戴的装备和身上同槽位那件比较时，两件都按**身上那件的强化等级**折算。理由是传承能把强化等级原样带到新装备上，所以这正是「换上之后」真实会有的状态。身上那件是 +0 时，两件都按 +0。旧装备强化满、新装备没强化这种差异，不进结论。
- **只比装备本身**：基础属性（含稀有度倍率、物品等级）、效果（随机词条 + 刻印）、buff（状态词条 + 套装 + 搭配的变化）。
- **算法**：用 `computeStats` 算「身上全套」和「把这一件换进去的全套」两次，差值就是这件的价值。所以套装件数和搭配的增减会自动算进去。三段分别算：只换基础、再加效果、再加 buff，逐段累计。
- **条件型效果的折算**：刻印和状态词条的收益依赖打法（破招后、满血时、对冻住的敌人……），按一张固定的「战力当量表」折算（每条刻印、每档状态词条、每个套装 / 搭配效果各一个值，写在数据里，和 `power()` 给首领动态难度用的是同一张表）。界面上标「条件型」。

### 3. 结论分级和推荐标记

| 结论 | 条件（按上面的口径，三段合计的战力变化） | 推荐标记 |
|---|---|---|
| 明显更强 | ≥ +5% | ▲▲（绿） |
| 略强 | +1% ～ +5% | ▲（绿） |
| 相当 | ±1% 以内 | ＝（灰） |
| 略弱 / 明显更弱 | -1% ～ -5% / ≤ -5% | ▼ / ▼▼（红） |
| **看打法** | 基础 + 效果的结论和 buff 的结论方向相反，而且决定胜负的是条件型效果 | ◆（金），不给 ▲ |

背包格子和掉落拾取提示上的标记都用这一套。**不许用含强化差异的总战力做推荐**：角色页顶部的总战力数字照常显示（那是你现在的真实实力），但比较和推荐从不读它。

## 十、搭配效果（混搭层面的协同）

套装（第二节第 2 条）是「同系列凑件数」；搭配效果是「**不同**装备一起穿时」的协同，和第三节的相互作用矩阵联动。目标是让混搭成为有意义的选择，而不是只追一套。

### 1. 四类搭配，全部数据化

规则表 `SYNERGY`（`src/gear/synergy.js`），每条：

```js
{ id: 'frostfire', name: '冰火交织', kind: 'reaction',
  when: [{ status: 'chill', slot: 'weapon' }, { status: 'burn', notSlot: 'weapon' }],
  effect: { type: 'crossApply', on: 'chill', apply: 'burn', ratio: 0.3 },
  text: '武器命中带寒意的敌人时，同时积累 30% 的灼烧（更容易触发「融化」）' }
```

`when` 的条件只能用这几样：
- 状态来源：哪件装备带哪种状态，可以限定槽位（翅膀 / 光幕不带状态，不算来源）；
- 系列件数；
- 武器流派；
- 职业（预留）。

`effect` 只能用状态系统已有的参数：积累倍率、反应伤害倍率、反应冷却、跨状态附加、持续时间、上限。所以**加系列、加状态、加职业都只加数据**，不加结算代码。

| 类 | 怎么生成 | 例子 |
|---|---|---|
| **A. 反应协同**（自动） | 由第三节的反应表**自动生成**：身上同时有某个反应两边的状态来源，就激活这个反应的协同。1 级：两种来源都有 → 这个反应的伤害 +15%、同目标反应冷却 1.5 → 1.2 秒。2 级：一种来源在武器上、另一种在非武器槽 → 再加「跨状态附加」（武器命中带 A 的敌人时，同时积累 30% 的 B） | 冰火交织（融化）、毒火交织（毒爆）、冰雷交织（碎冰）、毒血交织（毒血）。以后加一个反应，自动多一条协同 |
| **B. 元素共鸣**（自动） | 同一种状态的来源 ≥ 3 件（可以跨系列：霜烬的寒意 + 传说武器的寒意都算） | 寒之共鸣：冻结时间 +0.2 秒；灼之共鸣：灼烧层数上限 +1；雷之共鸣：麻痹触发时周围敌人积累 20% 感电。和第三节的同元素 √ 递减并存：共鸣给的是质变，不是更多数值 |
| **C. 系列搭配**（手写，少而精） | 两个指定系列各 ≥ 2 件 | 圣血（晨辉 + 血棘）：吸血溢出的部分转成护盾；导毒（惊雷 + 腐沼）：麻痹触发时给目标挂 2 层中毒；冻雷（霜烬 + 惊雷）：碎冰伤害 +30%；燎沼（燎原 + 腐沼）：毒爆半径 +40。首批 6～8 条，Codex 可以提案，我审定 |
| **D. 流派搭配**（手写） | 武器流派 × 某种状态来源 | 疾斩 · 感电：取消动作时也积累 10% 感电；崩山 · 寒意：对首领的「霜蚀」削霸体 15% → 22%；游刃 · 净化：破招 / 极限闪避 / 弹刀时，净化冷却缩短 4 秒。以后职业也走这一类（`when: [{ class: … }]`） |

**相互抵消的组合不禁止，但要明示**：身上同时有会互相抵消的来源（灼烧 + 流血 → 灼口烧掉你自己的流血；寒意 + 流血 → 冻结时流血暂停），生效栏用「注意」标出来，让玩家知道这是代价，不是 bug。灼口本身是转换（流血层变灼烧层），所以对专注灼烧的人也可以是故意的搭法。

**上限**：
- 同时生效的搭配效果最多显示和结算 6 条，按 A → B → C → D 的优先级取；
- 跨状态附加的比例在所有来源里取最高、不相加；
- 搭配效果折算进战力当量表（第九节第 2 条）。所以首领动态难度会跟上，对比时换一件装备导致搭配的得失也会算进结论。
